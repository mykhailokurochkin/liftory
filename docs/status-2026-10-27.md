# Стан початкової реалізації — 2026-10-27

## Що створено

Основна копія: `~/projects/personal-development/liftory` на Mac. Це окремий Git-репозиторій із власною identity та remote `https://github.com/mykhailokurochkin/liftory.git`. GitHub-репозиторій приватний і поки порожній: перевіреного першого коміту та push ще немає.

Підготовлені вихідні файли:

- pnpm/Turborepo, TypeScript, lint/format/typecheck конфігурація;
- Next.js Web/PWA з українським інтерфейсом Liftory;
- NestJS API, PostgreSQL/Drizzle schema та початкова SQL-міграція;
- Better Auth Google OAuth, allowlist та development identity тільки для loopback;
- вправи, окремі шаблони, фактичні тренування, підходи, історія й таймер;
- спільні Zod-контракти, IndexedDB/outbox, транзакційна ідемпотентна синхронізація;
- версійний service worker зі staging cache та збереженням старої повної оболонки при невдалому оновленні;
- unit/API/DB та browser offline-сценарії;
- CI workflow, Dependabot, Docker targets для Web/API, окремі local/runtime Compose-конфігурації;
- локальний `.env` із випадковими паролями й mode 0600, поза Git.

Це статус вихідного коду, а не підтвердження готовності всіх функцій.

## Фактично перевірено

- Сім Node-тестів service worker успішні на Mac: невдалий precache, порядок публікації, crash leftovers, збереження старої оболонки, виключення API/auth та зміна build version.
- Prettier успішно розбирає та перевіряє весь поточний код, включно з TS/TSX.
- `node --check` успішний для кореневих JavaScript-скриптів.
- Actionlint успішний для CI workflow.
- Обидва Compose-конфіги проходять `config --quiet`; runtime-конфіг перевірений лише з явними example credentials, без запуску контейнерів.
- `.env` ігнорується Git. Установка залежностей зупинена; процесів `pnpm install` не залишилось.

## Блокування й незавершені перевірки

Під час встановлення залежностей вільний диск опустився нижче 10 GiB (приблизно 9,6 GiB). Встановлення зупинене, БД не запускалась. Пізніший показник коливався близько 10,4 GiB; для продовження потрібен запас, бажано звільнити ще 5–10 GiB. Автоматичного очищення, Docker prune або перезапуску інших сервісів не було.

`pnpm-lock.yaml` та повне `node_modules` ще не створені. Typecheck, ESLint, Vitest, PostgreSQL integration, Next/API build, browser E2E й Docker image smoke **не виконані**. Живий CI, CD, реальний Google login, публічний liftory HTTPS і Safari/PWA на фізичному iPhone ще не підтверджені.

## Наступні дії

1. Перевірити вільне місце й завершити один `pnpm install`, отримати lockfile.
2. Запустити local PostgreSQL, міграцію та тести проти окремої тестової БД.
3. Виправити всі результати check/test/build; перевірити браузерний сценарій offline→reload→sync і вигляд на mobile/desktop.
4. Перевірити runtime Docker images, підготувати перший завершений коміт і провести CI та гілки main/develop.
5. Отримати Google OAuth client від власника за [інструкцією](google-oauth.md), перевірити реальний вхід.
6. Налаштувати окремий HTTPS dev-маршрут liftory, перевірити фізичний iPhone й лише після цього підключати його контрольовану доставку. Поточний home-server autodeploy не змінений.

Резервні копії залишаються відкладеними.

## Уточнення плану розгортання — 2026-10-28

Власник підтвердив початковий вибір: Next.js на Vercel; API, PostgreSQL і майбутній Redis на Pro. Браузер використовує `/api` на адресі фронтенду; Vercel передає запити через HTTPS-тунель. Redis поки не реалізований. Поточні Docker Web target та CI runtime smoke відображають попередній варіант і потребують адаптації; живого Vercel чи Liftory backend deploy немає. Наступний етап описано в [deployment.md](deployment.md).

Пауза встановлення залежностей залишається чинною. Важкі перевірки після її зняття плануємо на Pro; документація не підтверджує проходження збірок чи runtime-перевірок.

## Продовження — 2026-10-28

Власник відновив встановлення на Pro. Lockfile, збірки та автоматичні перевірки готові; dev Web опублікований на Vercel. Актуальний стан замість попередньої паузи — у [звіті перевірки](verification-2026-10-28.md). Зовнішні Google OAuth, тунель API та CI/CD ще не підтверджені.
